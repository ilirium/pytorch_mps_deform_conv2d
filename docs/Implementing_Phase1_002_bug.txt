================================ RESOLUTION (2026-07-05) ================================
Two separate things in this log:

1. Build: clean. -std=c++20 removed the 34 header warnings; only the harmless
   duplicate -rpath ld note remains.

2. "OMP: Error #15 ... zsh: abort": NOT a bug in the extension or the diag
   script's logic — the process died during `import torch`. The conda env
   links two OpenMP runtimes (torch's LLVM libomp + Intel libiomp5 via
   numpy/MKL); initializing the second aborts. Known issue, already worked
   around in the Makefile via `export KMP_DUPLICATE_LIB_OK := TRUE`, but the
   script was run directly (`python tests/diag_im2col.py`), bypassing make.

Fix: tests/diag_im2col.py, tests/diag_dispatch.py and tests/conftest.py now do
`os.environ.setdefault("KMP_DUPLICATE_LIB_OK", "TRUE")` BEFORE `import torch`,
so they work standalone. Also added `make diag` as the one-command path.

Clean long-term fix (optional): dedupe OpenMP in the env, e.g.
`conda install nomkl` or ensure a single llvm-openmp — then the workaround can
be dropped everywhere.
